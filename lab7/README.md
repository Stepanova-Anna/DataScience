### 1.3. Вопросы для отчета

**Вопрос 1: Какое сходство (число) система рассчитала между фильмами "The Martian" и "Guardians of the Galaxy"? Объясните, почему.**

**Ответ:**

Система рассчитала сходство = **0.577** между фильмами "The Martian" и "Guardians of the Galaxy".

**Объяснение:**
- "The Martian" имеет жанры: Sci-Fi
- "Guardians of the Galaxy" имеет жанры: Action, Comedy, Sci-Fi
- Общий жанр у них только один: Sci-Fi
- Косинусное сходство вычисляется как: 
  $$\text{cosine\_sim} = \frac{A \cdot B}{||A|| \cdot ||B||} = \frac{1}{\sqrt{1} \cdot \sqrt{3}} = \frac{1}{\sqrt{3}} \approx 0.577$$

**Вопрос 2: Какой главный недостаток Content-Based фильтрации вы видите на примере фильма "La La Land"?**

**Ответ:**

Главный недостаток Content-Based фильтрации — **отсутствие способности рекомендовать разнообразные фильмы за пределами уже известных предпочтений пользователя**.

На примере "La La Land": система рекомендует "Pulp Fiction" (сходство = 1.0), потому что оба фильма имеют только жанр "Drama". Однако:
- "La La Land" — это мюзикл, романтическая комедия, драма
- "Pulp Fiction" — это криминальная драма, чёрная комедия

Эти фильмы совершенно разные по стилю, настроению и целевой аудитории, но система не может это учесть, так как работает только с ограниченным набором жанров.

**Другие недостатки, проявившиеся в этом примере:**
1. **Ограниченность признаков** — система не учитывает режиссёра, актёров, сюжет, атмосферу
2. **Невозможность рекомендовать неожиданные фильмы** — пользователь никогда не узнает о фильмах из других жанров
3. **Холодный старт для новых пользователей** — проблема, но в данном случае не проявилась
4. **Отсутствие учёта качества фильма** — системе всё равно, хороший фильм или плохой

**Вопрос 1: Что означает полученное вами значение RMSE? Если бы RMSE было равно 0.5, а не полученному вами значению, что бы это значило для точности предсказаний?**

**Ответ:**

**Полученное значение RMSE = 0.9527.**

RMSE (Root Mean Square Error) — это среднеквадратичная ошибка предсказаний. Она показывает, насколько сильно предсказанные оценки отклоняются от реальных оценок пользователей.

**Интерпретация:**
- В среднем, предсказания модели отклоняются от реальных оценок на **~0.95 балла**
- Учитывая, что оценки в MovieLens ставятся по шкале от 1 до 5, ошибка ~1 балл — это приемлемый результат для базовой модели User-Based CF

**Если бы RMSE было равно 0.5:**
- Это означало бы, что модель предсказывает оценки с точностью ~0.5 балла
- Такая точность была бы значительно лучше (почти в 2 раза)
- Это позволило бы более точно рекомендовать фильмы пользователям
- Достижение RMSE = 0.5 на MovieLens 100k практически невозможно для простых моделей; для этого требуются более сложные методы (матричная факторизация, нейронные сети)

**Вопрос 2: Как изменится значение RMSE, если в настройках sim_options заменить 'pearson' на 'cosine'? Объясните, почему Пирсон часто дает лучший результат, чем Косинусное сходство, в контексте оценок пользователей.**

**Ответ:**

**Ожидаемое изменение:** RMSE при использовании косинусного сходства будет **немного выше** (хуже), чем при использовании корреляции Пирсона.

**Почему Пирсон часто лучше косинусного сходства:**

1. **Центрирование данных:**
   - Пирсон автоматически центрирует данные (вычитает среднее)
   - Это устраняет проблему "строгих" и "мягких" оценщиков — пользователей, которые ставят в основном высокие или низкие оценки

2. **Учёт индивидуальных особенностей:**
   - Один пользователь может ставить оценки в диапазоне 4-5
   - Другой — в диапазоне 1-3
   - Косинусное сходство может считать этих пользователей разными, даже если их относительные предпочтения одинаковы
   - Пирсон правильно считает их похожими

3. **Пример:**
   - Пользователь A: ставит оценки [4, 5, 4] → среднее 4.33
   - Пользователь B: ставит оценки [3, 4, 3] → среднее 3.33
   - Относительные предпочтения одинаковы (оба любят второй фильм больше других)
   - Косинусное сходство: векторы [4,5,4] и [3,4,3] имеют сходство ~0.99
   - Но если добавить пользователя C с оценками [5,5,5] → среднее 5:
     - Косинусное сходство между A и C: ~0.97
     - Пирсон между A и C: 0 (нет корреляции, потому что C не делает различий между фильмами)
   - Пирсон лучше определяет реальную схожесть вкусов

## Вывод

В ходе выполнения лабораторной работы были реализованы и проанализированы два базовых подхода к построению рекомендательных систем:

### Сравнение подходов:

| Критерий | Content-Based | Collaborative Filtering (User-Based) |
|----------|---------------|--------------------------------------|
| **Принцип** | Рекомендация похожих объектов | Рекомендация на основе вкусов похожих пользователей |
| **Требуемые данные** | Признаки объектов | Оценки пользователей |
| **Холодный старт** | Проблема с новыми пользователями | Проблема с новыми пользователями и объектами |
| **Разнообразие** | Низкое (рекомендует похожее) | Высокое (может рекомендовать неожиданное) |
| **Качество** | Зависит от качества признаков | Зависит от количества данных |

### Какой подход более перспективен для крупного онлайн-кинотеатра?

**Выбор: Гибридный подход, но с акцентом на коллаборативную фильтрацию.**

**Аргументы в пользу коллаборативной фильтрации:**

1. **Способность находить скрытые паттерны** — CF может рекомендовать фильмы, которые пользователь никогда бы не нашёл сам, основываясь на вкусах похожих пользователей

2. **Адаптивность** — модель автоматически адаптируется к изменению вкусов пользователей

3. **Не требует описания объектов** — для работы нужны только оценки, которые в кинотеатре легко собирать

4. **Масштабируемость** — современные методы (матричная факторизация, нейросетевые подходы) хорошо работают с большими данными

**Однако Content-Based также необходим:**

- Для решения проблемы **холодного старта** (новые фильмы без оценок)
- Для **улучшения качества** рекомендаций в гибридных системах
- Для **объяснимости** рекомендаций ("этот фильм похож на те, что вы смотрели")

**Вывод для крупного онлайн-кинотеатра:** Оптимальным решением является **гибридная система**, где:
1. Коллаборативная фильтрация является основным движком (70-80% веса)
2. Content-Based компонент используется для:
   - Обработки новых фильмов
   - Улучшения рекомендаций для новых пользователей
   - Повышения разнообразия рекомендаций
3. Современные подходы (матричная факторизация, нейронные сети) должны заменить простые методы KNN для повышения качества
